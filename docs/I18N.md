# Internationalization

pyenv-native ships Fluent catalogs under `locales/<bcp47>/`. English (`en-US`) is the source of truth. Other locales must contain the same message ids.

## Resolution order

1. `PYENV_LANG`
2. `config.toml` `ui.language` (`auto` or a BCP-47 tag)
3. OS UI languages
4. `en-US`

Command names, JSON keys, paths, package names, and versions stay English. Human docs (`README.md`, `docs/*.md`) stay English — they are not localized.

## Crate pin

Stay on `fluent-langneg` **0.13** (`unic-langid`). Do not take **0.14** (`icu_locid`) until `fluent-templates` depends on 0.14. A solo bump forks `LanguageIdentifier` types and still pulls 0.13 for the loader.

GUI doctor checks **process PATH after prepend**. Shell Integration cards describe **launch PATH**. Flag help (`--json`, `--force`) and MCP schemas stay English. Nested CLI `about` strings and `pyenv --help` command descriptions come from Fluent. Installer confirm/summary/progress copy comes from `install.ftl` (generated into `scripts/i18n/install-strings.sh` and `.ps1`). Doctor `command_hint` values stay English.

## GUI fonts

CJK, Arabic/Persian, and Devanagari glyphs use vendored Noto fonts in `crates/pyenv-gui/ui/fonts/` (OFL). Do not load Google Fonts from the network.

## Catalog layout

Each locale is a **directory**, not one giant dictionary:

```text
locales/<tag>/gui.ftl      GUI chrome, drawers, toasts
locales/<tag>/cli.ftl      CLI --help about strings
locales/<tag>/doctor.ftl   doctor check details
locales/<tag>/errors.ftl   structured PyenvError messages
locales/<tag>/install.ftl  installer confirm, summary, and progress copy
```

`en-US` is the source of truth. Other tags must contain the **same message ids**. Splitting by domain keeps files editable; Fluent-templates still loads the whole `locales/` tree at compile time. Command names, JSON keys, paths, and versions stay English.

Do **not** merge languages into one JS object. Preview HTML English and `t(id, args, 'fallback')` are disconnected-Tauri fallbacks only — not a second catalog.

Translations for non-English locales are authored in `scripts/i18n/overlays/<tag>.json` only. Run `python3 ./scripts/i18n/seed_locales.py` to copy `en-US` plus those overlays into `locales/<tag>/`. Do not keep a second overlay table in Python. Decorative punctuation (summary underlines) stays in the installer scripts, not in Fluent.

## Adding a locale

```bash
sh ./scripts/i18n/new-locale.sh <tag>
# or
pwsh -NoLogo -NoProfile -File ./scripts/i18n/new-locale.ps1 -Tag <tag>
```

Add `<tag>` to `LOCALES` in `scripts/i18n/seed_locales.py`, create `scripts/i18n/overlays/<tag>.json` with every `en-US` message id, seed, then run:

```bash
sh ./scripts/check-i18n.sh
```

`check-i18n.sh` (via `check-all.sh`) also requires overlay JSON key parity, generated `install-strings.sh`/`.ps1` to match `install.ftl`, and no hardcoded `showEmptyState` / `appendBadge` string literals in `app.js`.

Do not add `zh-TW` / `zh-Hant` catalogs.
